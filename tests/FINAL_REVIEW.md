# 1차 제출 전 최종 점검

점검일: 2026-11-01 (한국 시간)

## 평가

현재 구현 범위와 아래 한계를 명시하면 1차 제출에 사용할 수 있는 상태입니다. 이번에 실행한 테스트에서 제출을 막는 기능 오류는 남지 않았습니다. 모든 문서·브라우저·서비스 장애를 보장하는 평가는 아닙니다. 새 라이브러리나 프레임워크, DB 스키마 변경은 없습니다.

## 수정한 문제

- `document-reader.js`: 압축을 모두 푼 뒤에 크기를 검사하던 방식을 조각별 읽기로 변경했습니다. XML 하나당 1,500만 문자, 읽은 XML 합계 5,000만 문자, ZIP 내부 항목 1만 개를 제한합니다. 실제 DTD/엔터티 선언도 XML 분석 전에 거절하며 CDATA의 단순 문자열은 허용합니다. 입력 파일의 기존 20MB 제한은 유지합니다.
- `settings.js`: 취소된 검사의 finally가 새 검사의 버튼을 활성화하거나 늦게 도착한 추출 결과가 새 결과를 덮어쓰지 않게 했습니다. 세션 JSON이 잘못되거나 저장소 접근이 제한돼도 초기 화면 스크립트가 중단되지 않게 했습니다.
- `document-inspector.js`: PPTX 분량 기준도 음수·소수·문자열·최소/최대 역전을 검사해 잘못된 기준을 정상/불일치로 비교하지 않습니다.
- `bareun-proofreader.js`: 비정상 JSON 객체와 수정 후보를 처리하고, 잘못된 응답을 캐시해 재검사를 막던 경우를 방지했습니다.
- `api/proofread.js`: null 응답을 응답 형식 오류로 구분하고, 잘못된 수정 블록 하나가 전체 정상 응답의 처리를 중단하지 않게 했습니다. 해당 부분은 계속 판단 보류로 표시합니다.
- `korean-proofreader.js`: 추출 텍스트가 없는 문서는 실제 맞춤법 검사 불가로 기록합니다.
- `README.md`, `settings.html`: 오래된 DOCX 기능 설명과 실행 설명을 정정했습니다. 저장 결과에 문서 구성에 따라 전체 텍스트가 포함될 수 있음을 정확하게 안내합니다.

## 이번에 읽은 실제 파일

- `inspection_test_docx.docx`: 한국어 글자 묶음 12개와 Word 기본 정렬 5개 확인.
- `inspection_test_pptx.pptx`: 추출 텍스트 144자가 모의 외부 검사의 대상으로 포함되는지 확인.
- python-docx/python-pptx로 생성한 유효 DOCX/PPTX: 실제 업로드와 서식 비교·화면·JSON 흐름 확인. Office 렌더링 결과와 비교한 것은 아닙니다.
- 한컴 HWPX 샘플: 1,268문단·57,748자 추출과 서식 참조 확인.
- PDF 실파일 테스트 8개 및 `document_inspection_test.pdf`: 사용자 PDF는 1페이지·157자 추출, 형식 비교와 페이지/필수 단어 처리 확인.

문서 파일은 수정하거나 저장소에 복사하지 않았습니다. 이번 외부 API 테스트는 모두 모의 응답이며 실제 문서 텍스트를 바른에 전송하지 않았습니다.

## 보안 점검 범위

- Git 추적 파일의 secret 키 패턴/service_role JWT 검색에서 실제 비밀 키가 발견되지 않았습니다. 바른 키는 서버 환경 변수에서 읽습니다.
- 문서/파일명/결과는 textContent 또는 입력 값으로 표시하며, HTML 문자열이 실행되지 않는 것을 브라우저에서 확인했습니다.
- RLS 정책은 사용자 자신의 SELECT/INSERT만 허용하고, 사용량 테이블은 직접 접근 권한이 없습니다. 이 내용은 SQL 코드 검토이며 이번에 실제 DB 정책을 다시 실행/검증한 것은 아닙니다.
- 모의 서버 테스트에서 Origin/사용자 인증/동의/길이/사용량 예약을 거친 뒤에만 바른 호출이 진행됨을 확인했습니다. 키가 오류 응답에 포함되지 않는 것도 확인했습니다.
- 익명 계정 기반이므로 공개 서비스 전체의 공격·남용을 모두 방어한다고 보장하지 않습니다. 전역 사용량 제한은 유지합니다.

## 실행하지 않은 검증

- 이번 점검에서 실제 바른 API, 실제 Supabase DB/RLS 연결은 다시 호출하지 않았습니다. 사용자에게 확인된 기존 실연결 결과와 이번 모의 회귀 테스트를 구분합니다.
- 이번 수정 사항은 자동으로 Commit/Push/배포하지 않았습니다. Vercel 최신 배포 점검은 Commit/Push 이후에 해야 합니다.
- Word/PowerPoint/한글의 화면 렌더링 대조, 모든 브라우저/모바일 기기, 외부 보안 진단은 수행하지 않았습니다.

## 남은 제한

- DOCX/HWPX 정확한 페이지 수, PDF 원본 문단 정렬/% 줄 간격과 스캔 OCR은 검사 불가입니다.
- 복잡한 표 조건부 서식·변경 추적·도형/수식/이미지·일부 문자/상속 참조는 미확정입니다.
- 바른은 1회 검사 최대 1만 자/10묶음, DB 전역 일/월 한도와 대기 제한이 있습니다. 실패 요청도 사용량 예약에 포함될 수 있습니다.
- 맞춤법 후보가 없다고 전체 정상으로 보증하지 않습니다. 분할 문맥과 실제 미검사 범위를 결과에서 확인해야 합니다.
- 저장 결과 2MB 초과·네트워크 장애 시 DB 저장이 실패할 수 있으며 문서 검사와 JSON 다운로드는 유지됩니다. 익명 브라우저 세션을 지우면 이전 기록에 접근하지 못합니다.
- 매우 복잡한 파일은 제한 안에서도 브라우저 메모리/처리 시간이 많이 필요할 수 있습니다.

제출 시에는 지원 형식과 위 한계를 함께 설명하고, 최신 Commit/Push 후 Vercel Ready와 짧은 문서의 검사·저장·기록 조회를 마지막으로 확인하면 됩니다.
