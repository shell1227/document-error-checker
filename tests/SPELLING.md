# 한국어 규칙 검사

초기 버전은 외부 API, 새 라이브러리, 서버 또는 API 키 없이 브라우저에서 동작합니다.
LanguageTool의 공식 지원 목록에 한국어가 없고, 외부 웹 검사기의 비공개 호출 방식은
서비스 정책·변경·문서 전송에 의존하므로 이 구현에는 사용하지 않았습니다.
이 선택은 종합 한국어 검사기와 같은 품질을 제공한다는 뜻이 아닙니다.

지원하는 규칙은 코드에 모두 공개되어 있습니다.

- 되요 → 돼요 / 뵈요 → 봬요 / 아니예요 → 아니에요
- 됬다·됬어요·됬습니다·됬네·됬네요·됬죠·됬나요의 일부 활용
- 할/될/볼/갈/올/알/줄 + 수 + 있다/없다의 코드에 명시된 활용과 공백 누락

예: `저는 할수있어요. 내일 뵈요.` → `할 수 있어요`, `봬요` 수정 후보
`저는 할 수 있어요. 내일 봬요.`에는 후보가 없습니다. 이 경우에도 규칙 밖은 검사 불가입니다.

규칙에 맞는 후보는 fail로 저장하고 화면에는 '수정 후보'로 표시합니다. 원문 파일을 고치지 않습니다.
오류 후보가 없어도 전체 맞춤법 정상이라고 확정할 수 없어 항상 검사 범위 unknown을 포함합니다.
추출 자체가 불확실한 문서에서는 수정 후보도 unknown으로 표시합니다.
PDF에서는 페이지의 추출 텍스트를 사용하고, 조각마다 따로 검사하지 않습니다.
다른 문단·페이지·줄 사이를 붙여 검사하지 않습니다. DOCX/HWPX의 글자 묶음은 문단 단위로 읽습니다.
URL·이메일·백틱 구간을 제외하며 긴 어절 내부의 부분 문자열은 변경하지 않습니다.

표준 문장, 구어체, 이름, 인용문, 전문어, 어휘 선택, 조사, 일반적인 되/돼 구별이나 모든
띄어쓰기를 판단하는 사전/형태소 모델은 없습니다. 예를 들어 `먹을수있다`는 이 버전의
규칙 밖입니다. 인용된 오표기·고유명사는 의도적인 표현일 수 있어 후보를 사람이 확인해야 합니다.
유니코드 NFC/NFD를 자동 변환하지 않으며 글자 위치 offset은 원문 UTF-16 인덱스입니다.
전체 추출 텍스트를 검사합니다. 상세 후보는 500개까지만 보관하지만 그 뒤도 계속 검사하며 추가 검출 수를 알립니다.

Supabase의 기존 결과 JSON 안에 suggestion/ruleId/offset/length/source를 보관합니다.
새 SQL이나 컬럼은 필요 없습니다. 기존 기록을 열어도 당시 결과가 유지되며 재검사하지 않습니다.

```powershell
node tests/spelling.cjs
node tests/history.cjs
```

정상 문장·오류 문장·모호한 표현, 네 형식의 공통 적용, URL/코드 제외, 반복/줄 위치,
범위 제한, 불확실한 추출, 수정 제안의 모의 Supabase 저장 및 상세 조회를 확인합니다.
실제 DB는 기존 JSON 저장 경로를 그대로 사용합니다. 모의 API 테스트를 실제 DB 테스트로 간주하지 않습니다.

## 전체 범위 추가 검사 개선

`node tests/bareun-client.cjs`에서 문단 20개를 한 호출로 묶는 경우, 1,000자 초과 문단,
1만 자 한도, 부분 응답, 같은 위치/다른 위치의 반복 오류 및 겹친 범위의 동일 교정을 확인합니다.
규칙이 찾은 문단도 API 요청에 포함되고 같은 교정만 병합되는지 검증합니다.
임시 폴더의 실제 DOCX/PPTX/HWPX/PDF 파일이 있으면 추출기를 거쳐 API 응답 수신 범위와
미검사 범위의 합이 전체 대상 글자 수와 일치하는지도 확인합니다. API 응답은 모의입니다.
실제 문서는 저장소에 넣거나 외부로 전송하지 않습니다.
