# 최종 제출 점검 결과

점검일: 2026-11-17 (한국 시간)

## 판단

현재 구현 범위와 아래 한계를 명시하면 최종 제출 가능한 수준입니다. 이번 점검에서 재현한 글꼴/정렬 이름 처리 오류는 수정했고 관련 회귀 테스트가 통과했습니다. 이 수정은 로컬 상태이므로 Commit/Push 후 Vercel 최신 배포에 반영해야 합니다. 새 기능, 외부 라이브러리, DB 스키마 변경은 없습니다.

## 이번 수정

- `frontend/document-inspector.js`: `constructor`, `__proto__` 같은 이름을 글꼴 별칭 표에서 찾을 때 객체의 상속 속성을 읽어 PDF 검사에서 TypeError가 발생했습니다. 명시된 항목만 조회하도록 수정했습니다. 문서의 미지원 정렬값도 같은 방식으로 검사 불가로 구분합니다.
- `tests/inspection.cjs`: 특수한 글꼴 이름 입력과 잘못된 정렬값의 회귀 테스트를 추가했습니다.
- `tests/hwpx.cjs`: 실제 샘플이 100자보다 길어야 한다는 불필요한 테스트 조건을 비어 있지 않은 텍스트로 정정했습니다. 짧은 실제 파일의 서식 일치/불일치 비교까지 통과했습니다. 앱의 추출 제한을 완화한 변경은 아닙니다.
- 기존 영역별 테스트 보강 변경은 유지하고, 본 보고서와 README 링크를 추가했습니다.

## 실제 문서 파일

- python-docx/python-pptx로 영역별 DOCX/PPTX 정상 파일 2개와 제목/소제목/본문의 불일치 파일 6개를 생성했습니다. 서로 다른 글꼴과 24/16/11pt가 각 기준을 만족하면 정상이고, 바뀐 영역만 오류로 판정됐습니다.
- 네 형식의 구조 테스트 파일과 별도 제목 불일치 파일을 생성해 읽었습니다. 글꼴만/크기만/둘 다 다른 기준도 각각 비교했습니다. 역할 근거가 없는 문단을 60pt로 만들어도 제목으로 추정하지 않았습니다.
- 프리셋별 DOCX 12개(일치/글꼴만/크기만/둘 다 불일치)를 생성해 실제 업로드·검사했습니다.
- `inspection_test_hwpx.hwpx`: 7문단·84자 추출, 일반 문단의 글꼴/크기/정렬/줄 간격/필수 단어 일치·불일치 비교를 통과했습니다. 영역 구분에서는 비어 있지 않은 6문단이 본문 스타일로 확인됐습니다. 시각적 의미를 한글 프로그램과 대조한 것은 아닙니다.
- `document_inspection_test.pdf`: 1페이지·157자 추출과 서식 비교를 실행했습니다. 지정한 기준과 다른 글꼴/크기는 불일치, 원본 정렬/% 간격은 검사 불가, 페이지 수와 필수 단어는 일치였습니다. 별도로 생성한 PDF 8개와 tagged PDF의 영역별 비교도 통과했습니다.

사용자의 원본 파일은 수정하지 않았고 테스트 생성 파일은 임시 폴더에 보관했습니다.

## 실제 외부 연결 — 모의 테스트와 구분

### Supabase

`tests/supabase-live.cjs`를 실행해 실제 DB에 테스트 기록 2개를 저장하고 재조회했습니다. 중복 재시도 시 중복 기록이 생기지 않는 것, 서로 다른 익명 사용자의 목록/상세 격리, 다른 사용자 명의 INSERT 차단(RLS)을 확인했습니다. 이 두 기록 자체는 연결 확인용 합성 DOCX 결과입니다.

### 바른 + 배포 사이트 + 실제 기록 조회

`tests/bareun-document-live.cjs`를 실제 배포 주소에서 실행했습니다.

- 합성 DOCX 6문단·52자를 요청 1묶음으로 전송했습니다.
- 전송 대상 52자 모두의 응답을 수신했고 미검사 문자는 0자였습니다. 이는 문장 전체의 언어적 정확성을 보증한다는 뜻은 아닙니다.
- API 수정 후보와 로컬 규칙 후보를 함께 표시하고 동일 교정 중복을 제거했습니다.
- 실제 Supabase 저장 안내 후 기록 화면에서 결과를 다시 불러왔습니다.
- 바른 호출 1회가 사용됐으며 자동 반복 요청을 하지 않았습니다.

프로젝트에는 테스트 전용 익명 사용자들과 `__connection_test__A.docx`, `__connection_test__B.docx`, `__bareun_fulltext_test__.docx` 합성 기록 총 3개가 남습니다. 기존 사용자 기록을 변경하거나 삭제하지 않았습니다.

실제 바른 성공 확인은 DOCX 1회입니다. 네 형식별 장애·할당량 초과는 모의 테스트로 확인했으며 실제 서비스에 고의로 장애/한도 초과를 유발하지 않았습니다.

## 배포 및 정적 점검

- 배포 사이트의 프리셋 선택란·영역별 모드·영역 입력칸 6개를 확인했고 해당 페이지의 JavaScript 오류는 없었습니다.
- 수정 전 확인한 공개 프론트 파일 11개는 로컬 코드와 줄바꿈 정규화 후 일치했습니다. 이번 글꼴 이름 처리 수정은 그 이후의 변경이므로 추가 배포가 필요합니다. 서버 함수 소스 해시를 확인한 것은 아닙니다.
- JavaScript 구문 검사, HTML의 로컬 스크립트/CSS 참조, git diff 공백 검사가 통과했습니다.
- Git 추적 파일의 비밀키 패턴/service_role JWT 점검에서 실제 비밀키를 발견하지 않았습니다. 외부 전문 보안 진단이나 모든 의존성의 취약점 전수 조사를 수행한 것은 아닙니다.

## 남은 오류와 기능적 한계

실행한 범위에서 재현된 미수정 기능 오류는 없습니다. 다만 아래 항목은 계속 제한됩니다.

- DOCX/HWPX의 정확한 페이지 수, PDF 원본 문단 정렬/% 줄 간격과 스캔 OCR.
- 구조/스타일 없는 제목, 임의 스타일, PDF 태그 누락/오류. 본문 스타일로 꾸민 제목은 본문 기준이 적용될 수 있습니다.
- 복잡한 조건부 표 서식, 변경 추적, 수식/그림/차트 등의 일부 내용, 미지원 문자·상속 참조.
- 지정 글꼴 이름을 비교하며 실제 글꼴 설치·대체 렌더링을 판정하지 않습니다.
- 제한된 로컬 맞춤법 규칙, 바른의 정확도 및 1회 1만 자/10묶음·일/월 사용량·대기 제한. 후보가 없다고 전체 정상으로 판정하지 않습니다.
- 익명 브라우저 세션을 지우면 과거 기록에 접근하지 못하며, 2MB 초과 결과나 통신 장애는 DB 저장이 실패할 수 있습니다. 결과와 JSON 다운로드는 유지됩니다.
- 모든 브라우저/실제 모바일 기기, Office/한글의 시각적 렌더링 대조는 수행하지 않았습니다.

최종 제출 전 이번 수정과 테스트/보고서를 Commit/Push하고 Vercel 최신 배포 반영을 확인하면 됩니다. 환경 변수나 SQL을 새로 등록할 필요는 없습니다.
